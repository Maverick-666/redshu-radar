# 红薯雷达表格排序设计

日期：2026-09-10

## 目标

在不改变后端排序、数据库或指标口径的前提下，让用户能快速比较当前看板中的数值列。

## 范围

以下六个表头支持点击排序：

- 当前价格
- 24h 增量
- 上一小时
- 累计已售
- 爆品值
- 商品价值

商品名称、店铺、数据状态和人工阶段本轮不增加排序。

## 交互

- 页面首次加载时保持服务端返回的雷达默认顺序。
- 第一次点击某个数值表头按降序排列，再次点击同一表头切换为升序。
- 点击另一列时，该列从降序开始。
- 当前排序列显示向下或向上的箭头，并通过 `aria-sort` 暴露状态。
- 搜索或筛选先缩小可见商品集合，再对可见集合排序。
- 刷新页面后恢复雷达默认顺序，不持久化个人排序偏好。

## 数据规则

- 数值按真实数值比较，不按格式化后的字符串比较。
- `null`、未知值和页面显示为 `—` 的值在升序、降序中都放到最后。
- 24h 增量只有 `complete_daily` 状态参与数值排序；其他状态即使内部存在时段增量，也按未知值处理。
- 数值相同时保留服务端原有相对顺序，避免列表无意义抖动。

## 实现边界

- 排序只在浏览器内完成，不增加 API 参数或数据库迁移。
- 排序状态只包含 `key` 和 `direction`，由现有 `renderProducts` 渲染流程使用。
- 表头使用按钮获得键盘可操作性；不增加下拉框、多列排序或自定义规则。

## 验证

- 自动测试确认六个数值表头暴露排序键和可访问状态。
- 自动测试确认脚本包含降序首次、升降切换、空值置底和 24h 完整日级限制。
- `node --check` 验证脚本语法。
- 浏览器烟雾测试确认排序箭头、两次点击方向切换以及筛选后的排序正常。
- 完整 pytest 套件必须继续通过。
